# 羽田タクシー乗り場モニター

羽田空港のタクシー乗り場のライブカメラ（写真）を1分ごとに記録し、そこから「待っているタクシーの台数」や「お客様の利用の多さ」を、乗り場別・時間帯別の数字にするためのスキルです。

## 全体像（3段階）

| 段階 | 内容 | 状態 |
|---|---|---|
| 1. 記録 | 写真と、写真に添えられた時刻を、1分ごとに保存する（`scripts/capture.py`） | **できている**（疑似サイトでは試験済み。本物のサイトでは未確認 → まず診断を実行する） |
| 2. 数える | 写真から、待ちタクシーの台数・人数を数える | まだ。本物の写真を見てから作る（下の「第2段階」） |
| 3. 集計・報告 | 乗り場別・時間帯別・曜日別に集計し、図と短い所見にする | まだ。第2段階のあとで作る |

ユーザーは非専門家です。専門用語は避け、やることを1つずつ、短い日本語で案内してください。

## 先に知っておくこと（調べて分かった事実）

詳しい根拠は `references/site-notes.md` にあります。要点だけ:

- **写真は1分ごとに更新される**（公式の案内に明記）。1分より短い間隔で取りに行っても意味がなく、サイトに負担をかけるだけです。
- **Claudeのクラウド環境・GitHub Actions からは、カメラのサイトに届かない**（2026-11-20に確認）。海外のIPからの接続を受け付けない作りと思われます。取りに行く処理は、**日本国内の回線につながった、つけっぱなしの機器**（自宅のパソコン・小型機器など）で動かします。Claude側（クラウド）で取りに行こうとして時間を使わないこと。
- **ブラウザ（アプリ）の中で写真のピクセルを解析することはできない**。2026-08に、チームアプリ内でカメラ画像の動き解析を試し、配信元がCORSを許可していないため断念した経緯があります（表示だけなら可能）。だから、取得した機器側のプログラムで解析します。
- **写真は著作権の対象**です。公式サイトは「著作権法で認められる場合（個人的な利用など）を除き、許可なく利用できない」としています。個人的な分析の範囲にとどめ、**写真を他人に配る・公開する・Git（公開リポジトリ）に入れることはしない**。チームで共有するのは「数」だけにします。写真には通行人も写るので、数え方が固まったら、写真は残さず数だけ残す形に切り替えることを勧めます。

## 進め方

### A. まず、動かす機器があるかを聞く
日本国内の回線につながる、つけっぱなしにできる機器があるかを聞きます（自宅のWindows/Macパソコン、Raspberry Pi など、日本のレンタルサーバー）。なければ、何を用意するか（選択肢と費用感）を一緒に考えます。**スリープする機器・海外のVPN経由では動きません。**

### B. 道具が正しく動くか（機器の中だけで確認）
```
python selftest.py
```
疑似サイトで、記録ツールの動きを31項目で確認します。「すべて合格」と出れば、道具は正しく動いています（本物のサイトには出ません）。

### C. 本物のサイトで、ページの作りを確かめる（最初の1回）
```
python capture.py --diagnose
```
ページの見出し・時刻・写真のURLが読み取れるか、写真が取れるかを確かめます。**表示された内容を、そのまま貼り付けてもらってください**（写真は不要）。

貼り付けられた結果を、次の順に読みます。
1. 取得できているか（`× 取得できません` なら、国内の回線か・VPNを切ったか・写真ではなく別の理由か）
2. 「記録の対象になる写真」が、期待する枚数か（hnd1.php・hnd2.php は、それぞれ2乗り場ぶんの写真と見込む）
3. 見出し・ページ上の時刻が、写真ごとに取れているか
4. 取れていなければ、貼られた「ページの文字と画像の並び」を見て、`scripts/capture.py` の読み取り部分（`parse_sections`）を直す。直したら `scripts/selftest.py` に、そのページの形を再現する項目を足してから進める
5. うまくいっていれば、本番の記録に進む

### D. 本番の記録
```
python capture.py
```
1分ごとに記録を続けます（止めるときは Ctrl+C）。保存先は、ホームフォルダの `haneda-stand-data`（`--data-dir` で変更可）。公開リポジトリの中には置かないこと。手順の詳細（Windows向け）は `references/quickstart_ja.md`。

主なオプション: `--pages`（記録するページ）、`--once`／`--cycles N`（回数を決めて終わる）、`--keep-days N`（写真を残す日数。初期値30）、`--no-images`（写真を保存せず記録だけ）。

## 記録の形式

`haneda-stand-data/captures.csv`（Excelで開ける。UTF-8 BOMつき）。1つの写真につき、1分ごとに1行。

| 列 | 意味 |
|---|---|
| captured_at | 記録した日時（日本時間） |
| page / cam | ページ名（hnd1 など）／写真の番号（hnd1_1 = hnd1.php の1枚目） |
| label | ページ上の見出し（例: 【第１ターミナル】 第１乗り場の状況） |
| page_time | ページに表示されている写真の撮影時刻 |
| status | `saved`＝新しい写真を保存／`same`＝前回から更新なし／`new`＝新しい写真（保存しない設定）／`error`＝失敗（error列に理由） |
| image_url, bytes, width, height, sha1 | 写真の情報 |
| file | 保存した写真の場所（`images/日付/cam/…jpg`） |

`status` が `same` の行が続くのは、カメラ側の更新が遅れているか止まっているということです。集計では、`page_time` を写真の時刻として使い、`same` は重複として除きます。

## 第2段階: 数える（本物の写真を見てから作る）

写真が数日分たまったら、数え方を決めます。**いきなり作り込まず、まず実際の写真を何枚か見て（ユーザーに送ってもらう）、次の順で決める**こと。

1. **「利用頻度」を何で表すか決める**（ユーザーと相談）。候補:
   - 待っているタクシーの台数の推移（乗り場別・時間帯別）。台数が少ない＝お客様が多い、の目安
   - 行列の減り方（台数が減る速さ）＝乗られている回数の目安
   - 乗り場付近の人の数（写真が小さく、人は点にしか写らないので、精度は低い。参考値と割り切る）
2. **数える範囲（乗り場の車線）を、カメラごとに決める**。カメラは固定なので、写真に多角形を引いておけば、通りがかりの車を除いて数えられる。
3. **検出器を選ぶ**。第一候補は ultralytics の YOLOv8n（車・バス・トラック・人を数える。パソコンのCPUで1分ごとなら十分に動く）。入れる機器でインストールできるかを先に確かめる。入れられなければ、背景との差（車線の中の「ふさがり具合」）で代用する。
4. **人が数えた正解と比べて、誤差を確かめる**（20枚ほど。昼・夜・雨を含める）。誤差が大きいなら、「参考値」としてしか使えないと、ユーザーに正直に伝える。
5. 数える処理は `scripts/count.py` として足す。入力は保存済みの写真、出力は `counts.csv`（`captures.csv` の行と結びつけられる形）。写真を先に保存しておくので、数え方を直したあとで、過去の写真を数え直せる。

## 第3段階: 集計・報告
`counts.csv` から、乗り場別・時間帯別（15分・1時間）・曜日別の平均と、ピーク時間帯を出し、図と3〜5行の所見にまとめる。`same` の行や、写真が取れていない時間帯（`error`）は、欠測として明示する。夜間・雨・工事で数えにくい時間帯があれば、それも書く。

## 困ったとき

| 症状 | 原因と対応 |
|---|---|
| `× 取得できません` | 日本国内の回線か（VPNを切る）。携帯の回線でも試す。それでも同じなら、サイト側の都合の可能性。時間をおく |
| `写真が見つかりません` | ページの作りが想定と違う。`--diagnose` の結果を見て `parse_sections` を直す（`<img>` が無く、JavaScriptで写真を表示している場合は、ブラウザ操作の方式が必要） |
| `same` が何分も続く | カメラ側の更新が止まっている。公式も「回線の状況で遅れる場合がある」としている。欠測として扱う |
| CSVに書けない | Excelで開いたままになっている。閉じれば、ためていた分がまとめて書かれる |
| ディスクが足りない | 写真は1日あたり数百MB（2ページ・4カメラの場合）。`--keep-days` を小さくするか、数え方が固まったら `--no-images` にする |

## 守ること

- 個人的な分析の範囲にとどめる。写真を配らない・公開しない・Gitに入れない。共有は数だけ。
- 記録の間隔は60秒以上（コードで下限を設定済み）。取りに行く回数を増やさない。
- ユーザーの個人情報（氏名・連絡先など）は、サイトへの通信に含めない（名乗りは固定の汎用文字列）。
- 実サイトで確かめていないことは、確かめていないと書く。
