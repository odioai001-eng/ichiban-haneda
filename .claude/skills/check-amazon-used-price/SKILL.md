# Amazon 中古最安値・出品者数チェック

## なぜこのスキルが必要か

`resale_research.html`（せどりリサーチ電卓）は、商品ごとに「Amazon中古最安値」と「出品者数」を入力すると、妥当な価格帯と売却までの目安日数を計算するツール。だが、このツール自体にAmazonを自動取得（スクレイピング）する機能は意図的に組み込んでいない — Amazonの利用規約や、ボット検知の回避が絡む自動化は避けるべきだから。

その代わりこのスキルが、人間がAmazonの画面を見て数値をメモする作業を、対話的に・1商品ずつ・都度ユーザーに頼まれた時にだけ代行する。**これは常時動くスクレイピングボットではない。** ボット検知（CAPTCHA等）に出会ったら回避しようとせず、その場で止まってユーザーに手動確認を委ねること。これは技術的な限界であり、同時に守るべき一線でもある。

## 対象商品の特定

まず、何を調べればいいかを決める。

1. **ユーザーが商品名やISBN/JANコードを直接指定した場合** → それをそのまま使う。一番シンプルで確実なルート。
2. **「ツールの商品を調べて」のように指定がない場合** → `resale_research.html` から商品データを拾いに行く。ただし重要な注意点がある：

   `resale_research.html` は登録した商品を **ブラウザのlocalStorage**（キー: `resaleItems_v1`）に保存する。これは「そのブラウザだけ」に閉じたデータで、他の端末やブラウザからは見えない。ユーザーはBluetoothバーコードリーダー（KDC200等）と一緒にスマートフォンでこのツールを使っていることが多く、その場合データはスマホのブラウザにあり、このスキルが動くBrowser pane（別のブラウザコンテキスト）からは中身が見えない。

   手順:
   a. まず `mcp__Claude_Browser__tabs_context` で、`resale_research.html` を開いているタブが既にあるか確認する。あれば `mcp__Claude_Browser__javascript_tool` で `localStorage.getItem('resaleItems_v1')` を実行してJSONを取得する。
   b. 開いていなければ `https://odioai001-eng.github.io/resale-shop/resale_research.html` を新規タブで開いてから同様に確認する。ただしこれは高確率で空（`[]` または `null`）になる — その場合は「このセッションのブラウザにはスマホ側で登録した商品データが見えません（localStorageは端末・ブラウザごとに独立しているため）」とユーザーに伝え、対象の商品名を直接教えてもらうか、ツールの「書き出す」ボタンでコピーしたデータを貼り付けてもらうよう頼む。無理に何かを拾ったふりをしない。
   c. データが取得できた場合、`sellers`（出品者数）が空の商品を優先的に対象にする。`price` フィールドは追加時に必須入力のため常に何らかの値が入っているが、ユーザーが「相場を確認したい」と言った場合はそれも含めて全商品を対象にしてよい。

## Amazonでの調べ方

各商品について、以下を1件ずつ順番に行う（複数件を一気に並列で叩くとボット検知を誘発しやすいので、順番に・急がずに進める）。

1. 検索する。書籍はISBNがあれば `https://www.amazon.co.jp/s?k=<ISBN>` が一番確実。ISBNがなければ商品名（CD/DVDならアーティスト名も含めるとよい）で検索する。
2. 検索結果から、対象商品と一致するものを1件選んでページを開く。
3. 商品ページ内の「中古品」に関する表示（買い物カート付近の「中古品：¥X より」や「他の出品を見る」リンクなど）を探す。より正確に知りたい場合は、その「出品」リンクから出品一覧ページに飛び、コンディションが「中古」のものだけを見て、**最安値**と**件数**を数える。
4. `read_page` や `get_page_text` でページ内容を確認して数値を拾う。ページのレイアウトはAmazon側の都合で変わることがあるので、決め打ちのセレクタに頼らず、その都度「中古」「出品」「¥」といったキーワード周辺のテキストを読んで判断する。
5. 見つからなければ（中古の出品が無い等）、その旨を正直に報告する。無理に近い数字を作らない。

### ボット検知に出会ったら

「ロボットではないことを確認」「不審なアクセス」「セキュリティ確認」といったページや、画像认証（CAPTCHA）が表示されたら、**即座に作業を止める**。回避策を試みたり、別の手段で突破しようとしない。ユーザーに「Amazon側でボット検知が働き、この商品(または以降の商品)は自動確認できませんでした。お手数ですが手動でご確認ください」と伝え、そこまでに確認できた分だけ報告する。

## 報告フォーマット

必ず次の形式で簡潔に報告する（複数件は商品ごとに1行ずつ）：

```
商品名 → 中古最安値: ¥X、出品者数: Y件
```

見つからなかった商品は:

```
商品名 → 中古品の出品が見つかりませんでした
```

ボット検知で確認できなかった商品は:

```
商品名 → Amazon側のボット検知により確認できませんでした（手動確認をお願いします）
```

## ツールへの反映（できる場合のみ）

対象商品の特定で 1b の方法（`resale_research.html` の同一ブラウザタブ）からデータを取得できていた場合は、調べた数値をそのままlocalStorageに書き戻して画面に反映できる。`javascript_tool` で該当商品の `price` と `sellers` を更新し、ページの `render()` 関数を呼び出す（または軽くリロードする）。これを行う前に、反映してよいか一言確認する — 既存の手入力値を上書きすることになるため。

商品名を直接指定されただけの場合（ツール側のデータに触れていない場合）は、報告するだけでよい。ユーザーが自分でツールに入力する。
